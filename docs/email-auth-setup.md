# 이메일 가입·로그인 연결

가입, 이메일 확인, 비밀번호 로그인, 가입 확인 메일 재전송, 비밀번호 재설정, 세션 복원, 닉네임 변경, 현재 브라우저 로그아웃을 구현했습니다. Supabase 연결이 없으면 모든 인증 입력을 비활성화하고, 연결 후에도 메일 발송 검증 전에는 가입·재전송·비밀번호 재설정을 비활성화합니다. 기존 계정의 로그인은 별도로 사용할 수 있습니다.

## 공개 소스의 설정 범위

실제 운영 프로젝트 ID, 서비스 주소, 메일 계정과 발송키 상태는 포함하지 않습니다. 아래 주소는 예시이므로 자신의 배포 환경으로 바꿔야 합니다. 이 문서는 설정 절차를 설명하며 특정 서버의 현재 운영 상태를 보증하지 않습니다.

## 프로젝트 연결

1. HAS 전용 Supabase 프로젝트를 사용합니다. 기존 프로젝트를 선택할 때는 다른 서비스의 사용자가 섞이지 않는지 확인합니다.
2. `supabase/migrations/`의 SQL을 번호순으로 적용합니다. 이미 적용한 마이그레이션을 다시 실행하지 않습니다. 가입 시 프로필이 자동으로 만들어지며, 닉네임은 로그인 후 수정합니다.
3. 프로젝트 URL과 **publishable key**를 `.env.local`의 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`에 설정합니다. `.env.example`에는 빈 값만 유지합니다. service-role/secret key, DB 비밀번호, SMTP 비밀번호는 프런트엔드 환경변수에 넣지 않습니다.
4. 이메일 가입·비밀번호 로그인을 켜고, **Confirm email을 켠 상태로 유지**합니다. 최소 비밀번호 길이는 8자로 설정합니다.
5. Site URL을 `https://has.example`로 설정하고 다음 Redirect URL을 등록합니다.

```text
https://has.example/?auth=confirm
https://has.example/?auth=reset
http://127.0.0.1:5173/?auth=confirm
http://127.0.0.1:5173/?auth=reset
```

6. Supabase 기본 메일 템플릿의 `{{ .ConfirmationURL }}`을 사용해 가입 확인과 비밀번호 재설정 링크를 발송합니다. 사용자 제공 URL로 리다이렉트하지 않습니다.
7. `.env.local` 설정 후 개발 서버를 재시작하고 다시 빌드·배포합니다. 현재는 정적 Vite 사이트이므로 공개 URL과 publishable key가 빌드 시 포함되어야 합니다. 호스팅의 런타임 환경변수만 설정해서는 이미 배포한 번들이 바뀌지 않습니다.

## 인증 메일 발송

Supabase의 기본 발송 서비스는 테스트용이며 조직 팀원의 주소로만 전송합니다. 일반 방문자의 가입 확인·비밀번호 재설정을 열려면 발신 주소와 SMTP 서비스를 연결해야 합니다. 발송 제한을 피하려고 이메일 확인을 끄지 않습니다.

발신 도메인과 메일 서비스가 정해지면 SMTP 호스트·포트·계정·비밀번호와 발신 주소를 **Supabase의 인증 설정**에 저장합니다. 해당 비밀번호는 HAS 코드나 Git에 저장하지 않습니다.

자신의 메일 공급자에서 발신 도메인 인증, 발송량 제한, 키 만료와 교체 정책을 확인합니다. 계정별 발송키나 운영 상태를 저장소에 기록하지 않습니다.

SMTP 연결 후 로컬에서만 `VITE_AUTH_EMAIL_DELIVERY_READY=true`로 설정해 아래 흐름을 검증합니다. 실제 메일 전달·가입·로그인·복구까지 성공한 뒤 공개 빌드에서도 이 값을 `true`로 설정하고 재배포합니다. 이 플래그는 방문자 안내와 UI 개방을 위한 것으로 서버의 이메일 확인이나 접근 제어를 대체하지 않습니다.

## 실제 연결 후 확인

- 테스트용 이메일로 가입 → 확인 전 로그인 거부 → 확인 메일 → 로그인 상태 및 기본 닉네임 확인
- 새로고침 후 로그인 유지, 현재 브라우저 로그아웃
- 잘못된 비밀번호, 미확인 이메일과 재전송, 메일 발송 제한, 연결 오류 안내
- 비밀번호 재설정 요청 → 새 링크 → 새 비밀번호 저장 → 새 비밀번호로 로그인
- 만료·이미 사용한 링크에서 재설정 메일을 다시 요청할 수 있는지 확인
- 로그인만으로 본인·국적 인증이나 댓글 작성 권한을 얻지 못하는지 확인

자동 테스트는 인증 응답을 모의 처리한 UI 검사와 PostgreSQL 권한 검사를 포함합니다. 실제 메일 전달 및 Supabase 세션 연동의 통합 검증을 대체하지 않습니다.

공식 문서: [이메일·비밀번호 인증](https://supabase.com/docs/guides/auth/passwords), [메일 발송 설정](https://supabase.com/docs/guides/auth/auth-smtp), [Redirect URL](https://supabase.com/docs/guides/auth/redirect-urls).
